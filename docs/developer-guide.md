# Developer guide

BlueMolecule is plain JavaScript, HTML and CSS for the viewer, and Python standard library for the launcher and the
Linux window. The optional macOS app is a single Swift file. There are no runtime dependencies, no framework and no
build step for development: open `src/index.html` in a browser and you are running the current source.

## Repository layout

```text
src/                 the viewer: index.html, style.css and 22 JavaScript modules
launcher/            bluemolecule.py: command line, window selection, local server, Open Babel bridge
native/linux/        Qt WebEngine window (bluemolecule_qt.py), install.sh / uninstall.sh, desktop file, MIME types
native/macos/        WKWebView app (BlueMolecule.swift), Info.plist, "Install BlueMolecule.command"
native/icons/        app icons rendered from tools/icon.svg (generated, kept in the repository)
tools/               build.py, the icon, fixture and example generators, docs_screenshots.js
tests/               test suites, run_all.py, fixtures/ (example files), synth.js (synthetic macromolecules)
docs/                this documentation; docs/images/ is produced by tools/docs_screenshots.js
dist/                build output (not in the repository; published as release assets)
```

## Architecture

Every module in `src/` is an immediately invoked function that adds its part to one global object, `BM`. The same
files load unchanged in the browser and in Node.js, which is how the tests run the readers, writers and chemistry
without a browser. `tools/build.py` inlines the scripts and the stylesheet into a single `dist/BlueMolecule.html`.

| Module | Role |
|---|---|
| `elements.js` | Element data: symbols, masses, covalent and van der Waals radii, colours |
| `bigfile.js` | Reading files of any size as line arrays: chunked decoding, gzip streams, memory guard (`BM.bigfile`) |
| `parsers.js` | Format detection, the reader registry and the core readers: Gaussian, ORCA, XYZ, cube, Molden, fchk, MOL/SDF, PDB, GRO; ONIOM and QM/MM layers |
| `readers-qc.js` | GAMESS, NWChem, Q-Chem, Psi4, xtb, MOPAC, CP2K and Turbomole readers |
| `readers-struct.js` | Crystal, materials and MD readers: CIF, mmCIF, Mol2, CML, CJSON, VASP, Quantum ESPRESSO, CASTEP, XSF, Amber, CHARMM, LAMMPS, TRR, XTC, DCD |
| `writers.js` | The save-format registry, the basic writers and the calculation-input writers for 10 programs |
| `writers-struct.js` | Structure, crystal and periodic-code writers for Save as |
| `geom.js` | Bonds, distances, angles, dihedrals, formula, editing helpers |
| `chem.js` | SMILES reading and writing, bond-order perception, valences and hydrogens, 3D structure generation |
| `ff.js` | The clean-up force field (`BM.ff`) |
| `templates.js` | The building library: molecules, groups, ligands, coordination geometries (`BM.templates`) |
| `symmetry.js` | Point-group detection, symmetry operations, symmetrization (`BM.sym`) |
| `analysis.js` | Convergence series, RMSD (Kabsch), scan and IRC profiles, NMR sticks, MO levels (`BM.analysis`) |
| `isosurface.js` | Isosurfaces of volumetric data (surface nets) |
| `spectrum.js` | Spectrum simulation and the plotting component (canvas and SVG) |
| `reps.js` | Selection language, residue classification, sugar identification, display rows and presets (`BM.reps`) |
| `cartoon.js` | Cartoon, trace, ring and SNFG geometry (`BM.cartoon`) |
| `renderer.js` | The WebGL 2 renderer: instanced spheres and cylinders, per-atom styles, overlays, labels, picking |
| `examples.js` | Built-in examples (generated by `tools/make_examples.py`) |
| `native-bridge.js` | Talks to the host: macOS app, Linux Qt window, launcher or plain browser (`BM.native`) |
| `build-ui.js` | Build tools and the Build tab |
| `app.js` | The application: documents, panels, plots, dialogs, menus, preferences (`BM.app`) |

The readers, writers, chemistry, selection and analysis modules contain no DOM code, so they can be tested in Node.

## The data model

A reader returns a **Dataset**. Lengths are in Å, energies in Hartree, dipoles in Debye and frequencies in cm⁻¹.
The full shape is documented at `newDataset()` and `newFrame()` in `src/parsers.js`. In outline:

```js
{
  format, program, title,
  meta: { route, keywords, method, basis, charge, multiplicity, jobTypes, normalTermination, solvent, qmmm, … },
  frames: [{ Z, xyz /* Float64Array(3N) */, energy, energies /* named components */, label, converged,
             opt /* maxForce, rmsForce, maxDisp, rmsDisp, energyChange, gradNorm + …Thr, …Conv */,
             atomNames, resNames, resIds, scan, irc }],
  vibrations,      // { freqs, modes, ir, raman, sym, … }
  excitedStates,   // [{ index, energyEV, wavelengthNM, f, R, label, transitions: [{ from, to, coeff }], s2 }]
  charges,         // { Mulliken: [...], Hirshfeld: [...], … }
  orbitals, thermo, dipole, cell, volumes, nmr, jobs, optSteps, ircPath,
  layers,          // QM/MM and ONIOM: { scheme, atomLayer, frozen, active, linkAtoms, mmTypes, mmCharges, labels }
  warnings         // shown as "Reader notes"
}
```

Each frame is a complete geometry. For QM/MM and ONIOM, a frame is the full system at one optimisation step, and
`frame.energy` is the total only. Sub-calculation energies go into `frame.energies` (see the comment at the top of
`parsers.js`).

## Adding a reader

Register it from any module loaded after `parsers.js`:

```js
BM.registerFormat({
  id: 'myprog-out',                 // unique id
  name: 'MyProg output',            // shown to users
  extensions: ['out', 'log'],       // hints only: detection is by content first
  kind: 'output',                   // 'output' | 'structure' | 'topology' | 'trajectory'
  sniff: head => (/MyProg version/.test(head) ? 0.95 : 0),   // score for the first 64 KB of text
  parse: (textOrLines, fileName) => {                          // text, or an array of lines for big files
    const ds = BM.emptyDataset('myprog-out', fileName);
    // … fill ds.frames, ds.meta, ds.vibrations, …; throw new Error('readable message') on bad input
    return ds;
  },
});
```

Rules:
- **Sniff scores:** 0.9 or more means "certainly this format"; about 0.5 means "probably". A score is raised when
  the extension also matches. The strong built-in readers (Gaussian, ORCA, fchk, Molden) win against weaker
  scores.
- **Accept line arrays.** Big files arrive as `string[]`. Use a helper like `lines = t => Array.isArray(t) ? t :
  String(t).split(/\r\n|\r|\n/)` and never join a big array into one string.
- **Messages are for users.** Errors and `ds.warnings` should say what is wrong and what to do.
- **Write it from the format's public description**, never from another program's code
  ([clean room](vibe-coding.md#clean-room-statement)).
- **Add a fixture and tests.** Put a small example under `tests/fixtures/` (a trimmed real file is best, if you may
  share it) and add checks to the matching `tests/test_*.js`.

Binary formats use `parseBinary(bytes, fileName)` and `binary: true` instead of `parse`. See the DCD, TRR and XTC
readers in `readers-struct.js`, which also support slice-wise reading with a frame stride.

## Adding a save format

```js
BM.registerSaveFormat({
  id: 'myformat', name: 'My format', ext: 'myf',
  kind: 'structure',             // 'structure' | 'trajectory' | 'volume'
  needs: [],                     // e.g. ['frames'] or ['volume']: offered only when the document has them
  write: ctx => '…',             // ctx: { Z, xyz, bonds, cell, title, meta, atomNames, resNames, resIds, frames, … }
});
```

The new format then appears in **Save as…**. Tests go in `tests/test_writers.js` or `tests/test_writers_struct.js`,
ideally as a round trip that writes, reads back and compares.

## The hosts and the native bridge

`BM.native` hides how the page is hosted. Its `kind` is one of:

| `kind` | Host | Transport |
|---|---|---|
| `linux-app` | `native/linux/bluemolecule_qt.py` (Qt WebEngine) | QWebChannel: `bmHost.post(name, json)` |
| `macos-app` | `native/macos/BlueMolecule.swift` (WKWebView) | `webkit.messageHandlers` |
| `launcher` | `launcher/bluemolecule.py` serving the page to a browser app window | HTTP on `127.0.0.1` |
| `browser` | A plain browser | None: the page uses downloads and the clipboard API |

The messages are:
- `bmReady`;
- `bmSave`, which goes through the host's Save dialog;
- `bmCopy`;
- `bmObabel`, with one Open Babel contract for all hosts: `{op: 'formats'|'convert', input (base64), inFormat,
  outFormat, options[]}` → `{ok, output (base64), error}`;
- `bmRead`, which reads large files piece by piece in the Qt window;
- `log`.

Replies come back through `BM.native._resolve(id, result)`. Files opened by the host arrive through
`_receiveFile(name, base64)`, or `_receiveLargeFile(name, size, fileId)` for files of 32 MB and more.

**The launcher** chooses the window (Qt, Chromium-family app window or Firefox; see
[installation](installation.md#its-own-window-the-native-qt-window)). For the browser windows it runs a small
server:
- The server binds to `127.0.0.1` only, on port 47591 or the next free one.
- All paths are under a random per-session token: `GET /TOKEN/` serves the page, `GET /TOKEN/file/N/name` the
  files named on the command line, `POST /TOKEN/ping?state=…` is the heartbeat and `POST /TOKEN/obabel` runs Open
  Babel.
- The server checks the `Host` header (against DNS rebinding) and the `Origin` of POST requests.
- Open Babel runs with an argument list, never a shell. Format codes are validated, and options that could name
  files are refused.
- The launcher quits when the window has been closed or stops sending heartbeats.

## Building

```bash
python3 tools/build.py                 # dist/BlueMolecule.html + the package for this OS
python3 tools/build.py --target all    # also the other package
```

The build needs only Python 3. Two kinds of generated files are kept in the repository so that this stays true:
- `src/examples.js`: delete it and build again to regenerate it with `tools/make_examples.py` (needs numpy);
- `native/icons/*.png`: delete them to re-render them from `tools/icon.svg` with `tools/render_icons.js` (needs
  Node.js and Playwright).

The version number lives in `tools/build.py`, `src/app.js`, `launcher/bluemolecule.py` and
`native/linux/bluemolecule_qt.py`; keep them equal. `native-bridge.js` has its own bridge-protocol version.

`node tools/docs_screenshots.js`, run after a build, regenerates the screenshots in `docs/images/`.

## Tests

```bash
python3 tests/run_all.py             # unit tests: Node.js and Python (about a minute)
python3 tests/run_all.py --browser   # also build, then the browser tests (a few minutes)
python3 tests/run_all.py --big       # also the 600 MB / 1.2 GB files (slow; ~4 GB of RAM and disk)
```

Requirements:
- Node.js and Python 3. The tests were run with Node.js 22 and Python 3.13; the Python code also parses as
  Python 3.8;
- for the browser tests, Playwright with Chromium: `npm install playwright && npx playwright install chromium`.

Each suite can also be run alone, e.g. `node tests/test_parsers.js`.

| Suites | What they test |
|---|---|
| `test_parsers.js`, `test_parsers2.js`, `test_readers_qc.js`, `test_readers_struct.js`, `test_qmmm.js` | Readers and format detection against `tests/fixtures/` (expected values in `expected.json` files) |
| `test_writers.js`, `test_writers_struct.js`, `test_audit.js` | Writers, round trips, regression tests from the code audit |
| `test_chem.js`, `test_ff.js`, `test_templates.js`, `test_symmetry.js`, `test_analysis.js` | SMILES, bond orders, hydrogens, force field, building library, point groups, convergence analysis |
| `test_reps.js`, `test_cartoon.js` | Selection language, residue and sugar classification, presets, cartoon geometry (synthetic structures from `tests/synth.js`) |
| `test_native_bridge.js`, `test_launcher.py`, `test_native_packaging.py` | Host bridge, launcher (server, security, window selection with simulated browsers and a simulated Qt), packages and installers |
| `test_renderer.js`, `browser_*.js`, `test_bigfiles.js` | The renderer and the interface in headless Chromium (they save screenshots to `tests/shots/`), injection safety, large files |

**Fixtures.**
- Most example files were generated by `tools/make_fixtures.py`, which needs numpy, to imitate each program's
  output.
- The orbital fixtures come from `tools/mini_scf.py`, a small Hartree–Fock code written for the tests.
- `tools/make_big_fixture.py` writes the large logs used by `--big`.

Real outputs are very welcome as additional fixtures ([CONTRIBUTING.md](../CONTRIBUTING.md)), trimmed and free of
anything confidential.

## Conventions

- Plain modern JavaScript (`'use strict'`), no dependencies. The launcher and Qt window use the Python standard
  library only (plus Qt for the window).
- Keep readers and writers free of DOM code. Pure functions with explicit inputs are easy to test in Node.
- Escape everything that comes from a file before it goes into HTML: use `esc()` in `app.js`, or `textContent`.
  `tests/browser_xss_test.js` checks this.
- Every bug fix comes with a test that fails without it.
- Run `python3 tests/run_all.py --browser` before opening a pull request.
